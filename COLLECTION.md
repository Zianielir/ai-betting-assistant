# Сбор новостей

На этом этапе проверяем способы получения новостей и качество сохранения. Основной EDA текстов будет следующим этапом.

## Структура

```text
data/
  sky_sports/
    collect.py          # проверенная точка запуска для этого источника
    news.csv            # статьи, прошедшие предварительный фильтр АПЛ
    posts.csv           # отдельный формат коротких сообщений
    partial.csv         # заголовки, анонсы и неполные тексты
    review.csv          # неопределённые случаи и даты
    excluded.csv        # исключённые форматы, языки, не-статьи
    metadata.csv        # метаданные без полных текстов
    audit.json          # свежие результаты проверки маршрутов
    last_run.json       # итог последнего запуска
    runs.jsonl          # история запусков
    verification.json   # проверка повторного запуска
    records.jsonl       # локальное состояние для сохранения всех строк
    raw/                # локальные исходные ответы, сжатые gzip
  ...
EDA/
  описание источников.ipynb
  проверка_источников.xlsx
  source_audit.csv
  source_routes.json
news_ingest/            # общая реализация HTTP, извлечения и сохранения
research/
  Istochniki_APL.xlsx   # исходный список, без изменений
```

Папки есть для всех 34 строк исходной книги, в том числе для явно исключённых источников. `collect.py` появляется только после успешного извлечения статьи. Для недоступного источника нет заглушки, которая притворяется рабочим сборщиком: причина записана в отчёте. Коллекция официальных сайтов 20 клубов не раскрывалась; FPL, таблицы травм и чисто матчевые API исключены. У смешанных сервисов проверяются только статьи. Посты журналистов хранятся отдельно, если удаётся получить их через разрешённый рабочий маршрут.

## Установка

Нужен Python 3.11 или новее. Команды выполняются из корня репозитория.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

В конкретной папке источника используется общая реализация `news_ingest`; копировать один `collect.py` без остального репозитория недостаточно. Это позволяет исправлять общие ошибки и сохранять одинаковую схему у всех источников.

## Повторный запуск и новые статьи

```bash
python data/sky_sports/collect.py
```

Без дат сборщик проверяет последние три дня с перекрытием. RSS/API и текущая новостная страница используются для поиска новых URL; при необходимости подключается карта новостей. Существующие записи сохраняются, повторный URL не создаёт новую строку. `first_seen_at` — время нашего первого обнаружения, `last_seen_at` — повторного обнаружения. Это не доказательство времени первого появления новости в интернете.

Сборщик выполняет один проход и завершается. Внешний планировщик для будущего продукта пока не настраивался. Частоту опроса нужно выбирать по реальному объёму ленты, условиям источника и наблюдаемым пропускам. Непрерывная доступность и SLA не измерены.

Для обновления уже сохранённых текстов:

```bash
python data/sky_sports/collect.py --refresh-existing
```

Предыдущий текст при изменении сохраняется в `revisions.jsonl`. Запуски одного источника защищены файловой блокировкой. CSV обновляется атомарно по URL: новые строки добавляются, старые не удаляются при смене окна. Это upsert, а не слепое дописывание строк с дублями. `Ctrl+C` даёт сборщику завершить текущий запрос и сохранить результат.

## Историческое окно

```bash
python data/sky_sports/collect.py --start 2026-10-26 --end 2026-11-09 --archive --max-pages 220
```

Границы без часового пояса трактуются по Москве; начало включительно, конец исключительно. Согласованное окно — 26 октября–8 ноября 2026. В CSV timestamps хранятся в UTC с явным смещением. Неизвестное время не заменяется `modified_at`, `fetched_at` или полуночью. Отображаемая дата без времени сохраняется в `published_date_display`; такая статья остаётся на проверку.

Архив обнаруживается через доступный API, карты сайта и страницы архива. `lastmod` помогает отобрать кандидатов для скачивания, но окончательный фильтр использует оригинальную дату публикации. Бюджет страниц ограничивает обход; его исчерпание явно записано в `last_run.json`. Полнота сайта не гарантируется. Для Reach в архиве используются футбольные разделы; у RotoWire профили игроков не считаются статьями.

Общий повторяемый запуск всех проверенных маршрутов:

```bash
python tools/collect_all.py --start 2026-10-26 --end 2026-11-09 --archive --workers 6 --max-pages 220
```

## Отбор АПЛ

Сначала используются исходные метки лиги/клуба. Затем — названия клубов в заголовке и начале текста. Для неоднозначного упоминания в начале текста сохраняется очередь проверки: исторический контекст не равен актуальной новости об АПЛ. Одни слова `United` и `City` не подходят. Женские и молодёжные команды отмечаются для проверки. Для историй только об игроке нужна подтверждённая связь игрока с клубом; отсутствующая связь не выдумывается.

Это предварительный фильтр, не ручная разметка релевантности матчу. Нативные теги сохраняются без замены на наши метки. `selection_reason` и `date_provenance` позволяют проверить каждое решение. Словарь клубов — сохранённый справочник проекта от 26 октября 2026; при смене сезона его нужно обновить.

## Ошибки и доказательства

Для GOAL выбран компактный новостной sitemap с исходными датами и тегами. Глубокий редакционный каталог содержит тысячи материалов разных форматов и не исчерпан; это ограничение явно видно в отчёте. Диапазон найденных дат не доказывает полноту каждого дня.

Метка `full_text` означает, что извлечён основной текст страницы или API. Это технический результат, а не доказательство полноты редакционной версии; примеры нужно просмотреть в ноутбуке. Явно отмеченный закрытый контент и анонсы сохраняются как неполные.

`tools/check_saved_data.py` проверяет фактически сохранённые CSV и контрольные суммы. Проверка окна в этом скрипте относится к первичному сбору 26 октября–8 ноября; после добавления следующих периодов границы проверки нужно изменить.

На временные сетевые ошибки и HTTP 5xx выполняется до трёх попыток с паузами; для 429 учитывается `Retry-After`. Неудача одного маршрута не отменяет проверку других разрешённых RSS/API/архивов. Запрет robots, устойчивый 403, необходимость ключа, отсутствие английских материалов и ошибка парсера имеют разные статусы. Платные ключи и обход ограничений не используются.

`audit.json` подтверждает только реально проверенные маршруты. Наличие ссылки на документацию API не означает успешный запрос с ключом. `http_events.jsonl` хранит исходы запросов и число попыток; сырые ответы остаются локально. HTML 200 без основного текста не считается успешным извлечением статьи. Полнота, авторитетность и оперативность источников не выводятся из одного удачного запроса.

Проверки:

```bash
python -m unittest discover -s tests -v
python tools/verify_reruns.py
python tools/build_source_report.py
python tools/execute_source_notebook.py
```

Последняя команда исполняет ноутбук на локальных CSV с Python текущего окружения. В ноутбуке по умолчанию показываются короткие выдержки; `SHOW_FULL_TEXT = True` включает полные тексты локально. В репозиторий не добавляются сырые HTML, полный текстовый корпус и кэши. Их отсутствие после нового `git clone` ожидаемо: запустите сборщики заново. Это не разрешение использовать тексты для обучения или распространять их; условия источников проверяются отдельно перед таким использованием.
